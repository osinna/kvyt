# KVYT

Система бронювання квитків на події. Побудована як набір мікросервісів,
що спілкуються по HTTP і працюють поверх спільного Postgres.

## Сервіси

| Сервіс     | Роль                                                        |
|------------|-------------------------------------------------------------|
| `gateway`  | Єдина точка входу, на порту **8080**. Маршрутизація, JWT, `trace_id` |
| `identity` | Користувачі й автентифікація                                 |
| `catalog`  | Події, майданчики, місця                                     |
| `booking`  | Бронювання місць                                             |
| `postgres` | База даних, окрема схема на кожен сервіс                     |

Назовні відкритий тільки `gateway`. Решта сервісів портів не публікує —
до них можна достукатись лише зсередини мережі Docker.

## Вимоги

Docker Desktop (з ним іде `docker compose`). Більше нічого ставити не треба:
Python, залежності й база живуть у контейнерах.

Порт 8080 має бути вільний, на диску потрібно близько 2 ГБ.

## Запуск

```bash
make up
```

Команда збере образи, підніме всі сервіси, дочекається, доки вони стануть
healthy, і надрукує адресу gateway:

```
Gateway ready: http://localhost:8080
```

Перший запуск довший — Docker качає базові образи й збирає контейнери.
Файл `.env` створюється автоматично з `.env.example`, окремо копіювати не треба.

## Перевірка

Два ендпоінти є в кожного сервісу; знадвору доступні ті, що в `gateway`.

```bash
curl http://localhost:8080/health
```

Ліфнес: чи процес взагалі живий. Відповідає одразу, нічого не перевіряючи —
`{"service":"gateway","status":"ok","version":"...","scenarios":[]}`.

```bash
curl http://localhost:8080/health/ready
```

Реді́нес: чи сервіс готовий обслуговувати запити. `gateway` при цьому опитує
`identity`, `catalog` і `booking` і показує стан кожного:

```json
{"service":"gateway","status":"ok","deps":{"identity":"ok","catalog":"ok","booking":"ok"}}
```

Якщо хоч одна залежність лежить — HTTP 503, а в `deps` видно, яка саме.

Загальну картину дає:

```bash
docker compose ps
```

Усі сервіси мають бути в статусі `healthy`.

## Зупинка

```bash
make down
```

Зупиняє контейнери, дані в базі лишає — наступний `make up` підніме все
з тим самим станом.

## Повний скид

```bash
make reset
```

Зупиняє контейнери, **видаляє томи разом з базою** і піднімає систему заново.
Це спосіб повернутись до чистого стану, коли база зіпсована або незрозуміло,
що з нею відбувалось.

## Якщо порт 8080 зайнятий

`make up` впаде з помилкою на кшталт `port is already allocated`.
Подивіться, хто тримає порт:

```bash
lsof -i :8080
```

У виводі буде `COMMAND` і `PID` процесу. Далі два варіанти.

Якщо це щось ваше і його не шкода зупинити:

```bash
kill <PID>
```

Якщо процес не реагує — `kill -9 <PID>`. Перед тим, як убивати, подивіться на
`COMMAND`: якщо це не ваш dev-сервер, а щось системне, краще не чіпати.

Якщо це старі контейнери KVYT — зупиніть їх нормальним способом:

```bash
make down
```

Другий варіант — лишити чужий процес у спокої і віддати KVYT інший порт.
Тоді в `docker-compose.yml` у сервісі `gateway` змініть ліву частину:

```yaml
    ports:
      - "8081:8000"
```

і запускайте на `http://localhost:8081`. Права частина (`8000`) — це порт
усередині контейнера, її чіпати не треба.
